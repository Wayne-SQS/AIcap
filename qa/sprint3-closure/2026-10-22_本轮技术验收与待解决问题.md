## 待解决问题

1. **人工签认（阻断本目录整体闭环）**：实验三 AI 互动 13 行缺实际审查人、时间和签认文件。团队逐行核对后填写，并重新运行 `check_signoffs.py`。不能以源记录中的“团队处置”或自动测试代签。
2. **Sprint 3 功能口径**：需求基线把 US34—US37 和六项 AI 能力列为 Sprint 3；现有 GitHub 同步、画像/团队风险、规划生成和提案审核执行有实现与测试，但六项能力尚无逐项对照“输入→可解释结果→人工审核→执行/回流”的统一验收表。`frontend/src/data/seed.js` 中的六项说明是种子文案，不能独立证明交付。需与实验四已经签认的“25 条发布、8 条演示、3 条未开始、US37 并入 US36”清单逐项核对，明确未达 DoD 的演示项和后续实现负责人。
3. **模型语义质量**：现有会议 Agent 开发日志仍记录 Daily 摘要/状态推断、Review 冗余追问、Retro 行动语义、Refinement 条件句和确认指代等残余问题。自动契约与单次联调不能证明复杂语义稳定；继续使用人工审核门禁，按固定样例复验后才能提高质量结论。
4. **发布证据版本对齐**：实验四发布清单记载 Java 805 项及 Release Tag `v1.0.0`；当前工作树回归为 802 项，当前本地标签列表无 `v1.0.0`。需核对交付压缩包、签认清单、Git 标签与本轮新增提交对应的代码快照；不要把不同快照的测试数量合并陈述。本机只有 Java 21，本轮通过覆盖参数使用 Java 21，正式发布环境仍按项目 Java 23/CI 配置复核。
5. **上轮已登记技术债**：UML 草稿仍为本地保存；会议 Agent 日志记录跨浏览器保存意图恢复和部分模型质量待办。按团队既定进阶计划跟踪，不计入本轮已完成项。
