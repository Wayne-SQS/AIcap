# 2026-10-22 会议语义固定样例复验记录

## 边界

- 本轮用**固定样例**对 Daily、Review、Retro、Refinement 四类会议各跑一次真实模型分析。
- 结果只作为复验证据；**没有执行审核或业务写入**，人工审核门禁保持不变。
- 单轮样例通过不能证明复杂语义稳定；结论只覆盖本次样例。

## 样例与执行

| 类型 | 端点 | 样例要点 |
|---|---|---|
| Daily | `POST /api/meetings/{id}/analyze`（`daily_scrum`） | “US36 功能做完但测试没补、先不算完成”；T12 等接口阻塞；数据旧未同步 |
| Review | `POST /api/meetings/{id}/review/analyze`（`sprint_review`） | US34 验收通过；US35 只是演示；US36 测试未补；US37 不能算完成 |
| Retro | `POST /api/meetings/{id}/retro/analyze`（`sprint_retrospective`） | “以后每轮第一天跑回归”（提议）；高思晗负责写清单；罗子涵清理测试库残留 |
| Refinement | `POST /api/meetings/{id}/refinement/analyze`（`backlog_refinement`） | “如果接口没通就先做前端”；“刚才说的那个故事”；US38 导出范围未定 |

执行脚本：`qa/sprint3-closure/semantic_recheck.py`（建会议 → 调分析 → 存档，不审核）。
原始输出：`qa/sprint3-closure/evidence/semantic-recheck-2026-10-22.json`。
四类分析均返回 200，并以 `analysis_id` / `storage_status` 落库为待审分析。

## 本轮观察

### Daily

- US36 被写成“功能完成、测试未补、团队明确先不算完成”，提案只把状态改为**进行中（1）**，没有改为已完成；理由引用了“测试还没补、先别算完成”的原文。
- US34 依据“可以验收”提出完成，进入待审。
- T12 阻塞、接口时间未知、数据旧未同步，均保留为 **open_questions**，没有编造负责人或日期。
- 与开发日志记录的“状态推断”问题相比，本轮样例没有出现把“功能能点”直接等同于“已完成”。

### Review

- 明确区分：US34 验收通过；US35 只是演示、不算验收；US36 未给结论；US37“不能算完成”。
- 只对 US34 生成状态提案，其余保持未知，没有把演示写成验收。
- 没有出现对已给信息（如 US37 原因）的重复追问。

### Retro

- 只把**明确有人负责**的两条写成行动项：高思晗“把回归写进检查清单”、罗子涵“清理测试库残留（下次联调前）”。
- “以后每轮第一天先跑一次全量回归”属于提议，未被改写成已决定，保留为 open question。
- 与开发日志记录的“行动语义”问题相比，本轮样例没有把讨论意见冒充为决定。

### Refinement

- “如果接口没通，就先做前端展示”保留了条件句，没有拆成无条件任务。
- “刚才说的那个故事”被标记为**指代不明**（open question），没有编造具体故事编号。
- US38 导出功能按“范围未定、建议先入需求池”处理，没有创建故事；US37 影响说明属已有故事修改，超出本切片范围，保留为待确认。

## 结论

- 四类固定样例本轮未复现开发日志记录的残余问题（Daily 状态推断、Review 冗余追问、Retro 行动语义、Refinement 条件句与指代）。
- 这只能说明**本轮样例**通过；复杂会议、多人交叉发言与长上下文仍需人工审核。
- 审核/执行仍由人完成，模型输出不自动改业务数据。

```powershell
python qa/sprint3-closure/semantic_recheck.py
```
