# 爱管理 · 测试用例设计文档(前后端)

> 版本:v1.1(实测回填) · 角色:测试人员 · 被测对象:「爱管理」团队工作台
> - 前端:根目录 `index.html`(像素风 8 视图,离线 localStorage 演示 + 在线 API 双模式)
> - 后端:`backend/` FastAPI + MySQL(4 用户/20 故事/16 任务种子数据)
> - 依据:《爱管理_需求基线与AI智能体需求交接_v2.0.md》、《2026-09-06-aiguanli-backend-design.md》及代码内验收口径
> - 实测标记:✅ 通过 · ❌ 失败/缺陷 · ◐ 设计观察(非阻断)

## 1. 范围与测试策略

| 层级 | 对象 | 方法 | 环境 |
|---|---|---|---|
| 接口(后端) | REST API(auth/stories/pool/tasks/dashboard/health) | pytest + FastAPI TestClient,独立库 `AIcap_test` | MySQL:3307(Docker) |
| 联调(后端) | 同上,真实 HTTP 服务 | httpx/curl 冒烟 + 数据一致性核对 | 8001 → `AIcap_qa` |
| 前端功能 | 离线演示模式(纯 localStorage) | Playwright + Edge(msedge channel) DOM/交互 | http://127.0.0.1:8090 |
| 前后端联调 | 在线模式(登录→读 API→写 API) | Playwright + 真实后端 8001 | 同上 + AIcap_qa |
| 一致性 | 双视角共享库 | 登录后操作→刷新断言服务端状态 | 同上 |

测试设计技术:等价类划分、边界值、错误推测、权限矩阵、数据口径核对。
每条用例含:ID、模块、标题、优先级(P0 冒烟/P1 核心/P2 一般)、步骤、预期、实测。

**执行结果总览:后端 41/41 通过(原 34 + 缺陷回归 7);前端 E2E 48/48 通过(含 BUG-FE-01 回归)。4 项缺陷已修复并经测试复核。**

## 5. 结论与缺陷摘要

### 通过率(修复后复测口径)
- 后端接口自动化:**41/41(100%)**(原 11 + 扩展 23 + 缺陷回归 7)
- 前端功能(离线+在线 E2E):**48/48(100%)**(含 BUG-FE-01 回归 OE-12)
- 多用户数据一致性(拖拽→PATCH→刷新):**通过**

### 缺陷清单(修复后状态:4 项均已修复并通过复核,详见 `qa/缺陷清单与修复建议.md`)
| 编号 | 级别 | 模块 | 描述 |
|---|---|---|---|
| BUG-FE-01 | 中 | 前端登录态 | 页面刷新后,已登录用户的状态芯片停留在"在线 · 未登录",user-chip/logout 隐藏(bootstrap 中 updateChip 在 /me 成功前调用且成功后未再次调用) |
| BUG-BE-01 | 中 | stories/dashboard | 缺字段域校验,status=5/sprint=99 可入库,dashboard total 与状态桶合计口径不一致 |
| BUG-BE-02 | 低 | pool/stories | priority 无枚举校验,任意字符串可入库 |
| BUG-BE-03 | 中 | stories | owner_id 引用不存在用户时返回 500,应返回 400/404 |

> 详细复现与修复建议见 `qa/测试执行记录_后端.md`;执行入口见 `qa/README.md`。
