## 1. RAG 的三个问题

### ① 完全没配 embedding（根因）

`backend/.env` 里只有 `AICAP_LLM_*`，没有 `AICAP_EMBEDDING_API_KEY` / `_MODEL`。
`RagProperties.Embedding.settingsReady()` 要求 key + baseUrl + model 三项齐全，
缺一项 → `RetrievalService.retrieve()` 第 100 行直接返回 `configured=false`，
`KnowledgeIndexer.rebuild()` 直接跳过索引。**RAG 等于从来没开过。**

### ② 默认供应商是死路（更坑的一点）

`application.yml` 原默认 `aicap.rag.embedding.base-url = https://api.deepseek.com`。
实测：拿 `.env` 里那把 DeepSeek key `POST /embeddings` → **404**。
DeepSeek 不提供 embedding 端点。也就是说就算把 key 和 model 都填上，
按默认配置也必然打不通，而日志只说「向量化服务返回 HTTP 404」，看不出是供应商选错。

已改：默认改指 `https://api.siliconflow.cn/v1` + `BAAI/bge-m3`（免费、1024 维、
国内直连，与 `dimension` 默认值一致）。

### ③ 文档源把开发日志也索引进去了

10-13 文档三层重构后，`docs/_process/` 收的是开发日志与历史交接稿（单文件最大 150KB）。
`KnowledgeSourceScanner` 原来只跳过隐藏目录和 node_modules，这些过程记录会进知识库 →
问「现在怎么定的」可能捞回三个月前的中间方案。

已改：新增 `aicap.rag.docs-exclude`（默认 `_process`），`scanDocs` 与 `scanOne`
用同一套口径排除一级目录。

## 4. 环境坑（今天踩到的）

| 坑 | 表现 | 处理 |
|---|---|---|
| **shell 里有 `SERVER_PORT=60076`** | 后端起在 60076 而不是 8080，且该端口被 WorkBuddy 自身占用 → 启动失败 | 启动时显式 `$env:SERVER_PORT='8080'` |
| **后端在 DB 就绪前启动会「半死」** | 只响应 `/api/health`，其余路径（含 swagger）全部挂住；线程栈里 exec 线程全是空闲，请求根本没进 Servlet | 重启即可。今天 17:04 那个实例就是这个状态 |
| JAVA_HOME 默认是 JDK 8 | 编译失败 | 显式 `C:\Program Files\Java\jdk-23` |
| Docker Desktop 需手动启动 | 3307 MySQL / 6333 Qdrant 都不在 | 手动打开 Docker Desktop |
| 本机 MySQL 8.0（3306） | root / aiguanli 都被拒，连不上 | 用 Docker 的 3307 |
