# 用户故事地图看板：项目管理知识摘要

> 用于指导"用户故事地图可视化看板"的界面设计。不含任何前端实现。

## 1. 原始定义与二维结构（Jeff Patton《User Story Mapping》）

三层结构：

- **Backbone（主干）**＝用户活动（activities），按用户真实完成顺序从左到右排列，构成叙事骨架。
- 其下二级＝**用户任务/步骤**（tasks/steps），是活动内部的子步骤。
- 最下层＝**用户故事**（stories），是任务的实现细节，按优先级从上到下排列。
- **Walking skeleton（行走骨架）**＝横穿整条 backbone 的最薄一条端到端故事切片，验证骨架能走通。

**为什么是二维的**：横轴＝用户活动流程顺序（叙事/时间），纵轴＝优先级、细化程度、发布切片粒度。切片横线的语义就是"这条线以上先做"。

→ **界面含义**：必须提供两个正交的视觉通道——横向分组（活动列）与纵向分层（切片带）。拖拽改变的是纵轴优先级，不能被误读为改变横轴流程顺序（横轴顺序应锁死或加确认）。

## 2. 纵轴切片的经典切法与语义

- **按发布/迭代切**（Release slices）：MVP、Release 1、Release 2；每个发布切片可再细分为 Sprint 切片，二者是"发布 → 迭代"的父子关系。
- **按优先级切**：MoSCoW（Dai Clegg，DSDM 方法）Must / Should / Could / Won't；Kano（狩野纪昭）基本型 / 期望型 / 兴奋型，用于区分"缺了就不满"与"多了才惊喜"。
- **按细化程度切**：Epic → Story → 可交付切片（遵循 INVEST），越往下越具体。

**切片在图上就是横线，语义是"这条线以上先做"。**

→ **界面含义**：横线需可命名、可拖拽、可锁定；同一时刻只允许一种切片轴生效（发布 / 优先级 / 细化），换轴时保留原轴位置以免"失忆"；Won't 应有独立收纳区而非删除。

## 3. 着色 / 泳道 / 热力维度在真实工具中的用法

- **Jira**：卡片颜色可按 issue type / priority / assignee / epic / JQL 查询着色；泳道按 assignee 或 epic（团队管理的 backlog）。
- **Azure DevOps**：用"卡片规则"按字段条件上色，泳道按负责人或 backlog 层级。
- **Miro**：仅自由标签色，无语义约束。
- **StoriesOnBoard / FeatureMap**：按发布、人物、状态、主题或团队泳道着色。

业界最常见 6 个维度及其回答的管理问题：

1. **负责人/团队** → 负载是否均衡
2. **优先级** → 先做什么
3. **状态/进度** → 哪里卡住
4. **迭代/发布切片** → 这个版本装了多少
5. **工作项类型/标签** → 结构是否健康（功能 vs 技术债）
6. **截止时间/风险** → 哪里会延期

→ **界面含义**：着色做成单选的"图层 + 常驻图例"，默认按状态，禁止叠加；泳道与着色是两套独立机制，别用颜色兼职泳道。

## 4. 紧急程度 / 时间风险的可视化惯例

档位与阈值（工具多由用户自定义规则，下列为惯例）：

- **延期 overdue**：截止日已过 → 红
- **即将到期 due soon**：D-3 或 D-7 以内（短迭代用 3 天，月级用 7 天）→ 橙 / 黄
- **正常 on track** → 绿
- **无计划日期 unscheduled** → 灰（中性状态，不等于安全）

**色盲友好**：红绿是最差组合；不得只靠色相区分，必须叠加图标（! / 时钟）、文字 D-n、边框或纹理；非文本对比度要足够；绿色宜偏向青绿、红色宜偏向橙红；应提供"高对比/色盲模拟"开关。

→ **界面含义**：图例必须写明阈值规则（如"≤3 天"）而不只写颜色名；灰色＝未知，需在计数中单列，不能与"正常"合并。

## 5. 信息密度与缩放（overview / zoom）

- **Jira**：card layout 紧凑/展开切换 + 逐字段开关。
- **Azure DevOps**：卡片样式 compact / expanded，按 backlog 级别配置显示字段。
- **Miro**：连续 zoom，缩小后隐藏文字仅留色块。

**紧凑视图保留 3~5 项**：① 编号 + 标题（截断）② 负责人头像 ③ 状态/进度点 ④ 优先级或 D-n 风险标记 ⑤（可选）故事点。

**应隐藏**：描述、验收标准、评论数、附件、子任务明细、完整标签列表、时间戳。

→ **界面含义**：为卡片定义"缩略信息集"与"完整信息集"两套模板，按 zoom 阈值切换（如 <60% 只留标题 + 色块）；文字截断而非换行，保持卡片等高，纵向切片才读得出来。

## 6. 常见错误用法 / 反模式

- **彩虹图**：所有维度同时上色，颜色失去区分度。
- **一色多义**：同图上红既表示延期又表示缺陷 —— 颜色须由图例唯一绑定。
- **总览塞满文字**：缩小后仍渲染全字段，看不清切片分布这个"形状"。
- **纵轴漂移**：卡片位置与切片线脱节，地图退化为装饰墙。
- **泳道无限扩张**：纵向无限滚动，丧失一屏概览能力。
- **一次性交付物**：缺少"当前迭代线"标记与回流看板的机制，地图变成静态文档。
- **假精确**：给未排期项硬塞日期。

→ **界面含义**：默认单图层、图例常驻、切片线显眼、卡片支持降级渲染；未排期项显示为灰色而非默认日期。
