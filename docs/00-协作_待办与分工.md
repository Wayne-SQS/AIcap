## 1. 这个项目是什么（30 秒版）

> **一个由「本」统筹的 AI 团队办公室。**
> 三个智能体同事各司其职，人只跟「本」说话；所有会改动项目正式数据的结论，**先过人审，再落库**。

四个角色：

| 角色 | 名字 | 干什么 |
|---|---|---|
| **主管** | **本** | 对人沟通、看全部同事产出、派活、启动同事的服务 |
| 会议 | **译** | 把会上说的话译成任务、负责人、排期 |
| 画像 | **衡** | 说清每个人做了什么、扛了多难、有什么风险 |
| 画图 | **绘** | 把项目数据或一句话画成可交互的图

## 3. 还没做的（按优先级，可直接认领）

### 🔴 P0 · 决定"是不是一个产品"

**① 悬浮像素头像 + 对话框**
- 干什么：右下角常驻「本」的像素头像，点开是对话框，能问项目情况、能派活给三个同事
- 依赖：后端 `/chat` + `/chat/stream` 已就绪，**只差前端**
- 工作量：纯前端，不碰后端
- 为什么最优先：没有它，"办公室"这个故事就只剩 PPT

**② 对话过程时间轴**
- 干什么：对话框内按 `seq` 渲染"本 → 找了谁 → 说了什么 → 拿回什么"
- 依赖：SSE 事件流（11 类信封）后端已就绪，前端零消费
- 工作量：和 ① 一起做，边际成本几乎为零

**③ 运行时证据校验**
- 干什么：把 `invented_assignment` / `invalid_evidence` / `incomplete_analysis` 三条检查移植进 ai-service 的 validate 节点
- 依赖：有原始实现可移植
- 工作量：唯一要动后端的一项，但改动面小

### 🟡 P1 · 决定"好不好用"

**④ 画像域后台消费者**
- 干什么：给 `profile/` 加 `ProfileWorkerTask implements WorkerTask`，让主管能派活给它
- 依赖：照 `PlanningWorkerTask` 抄

**⑤ 编排层进生产**
- 干什么：`deploy/compose.yaml` 加 orchestrator 服务 + nginx 加 `/orchestrator/` 路由（`proxy_buffering off`）

### ⚪ P2 · 决定"能不能讲"

**⑥ 重写 `02-契约/会议Agent_外部功能基线与新架构落点.md`**（"两代并存"前提已失效）
**⑦ 统一对外文案**（README / 演示脚本）

## 4. 分工建议

| 活 | 建议谁接 | 理由 |
|---|---|---|
| ① 悬浮头像 + 对话框 | 前端同学 | 纯 Vue，不碰 Java |
| ② 时间轴 | 同上，一起做 | 同一处 |
| ③ 证据校验移植 | Java/后端同学 | 唯一动后端的 |
| ④ 画像域消费者 | Java/后端同学 | 和 ③ 同栈，可串行 |
| ⑤ 编排层部署 | 熟悉 Docker 的同学 | 独立，不阻塞 |
| ⑥⑦ 文档 | 可并行，谁有空谁做 | 不阻塞开发 |

**依赖顺序**：① ② →（看到真实交互后）→ ③ → ④；⑤ 独立；⑥⑦ 独立。

**纪律（避免再反复改）**：
1. 只做 P0，做完重新评估，**不并行启动未拍板的工作流**
2. 改代码必须同批改文档
3. 禁止为"记录过程"新建文档——开发日志追加到 `_process/`
4. 智能体名单只在 `01-产品/智能体产品契约.md §2.1` 定义
