# AI 任务提交与成员能力画像智能体 · 介绍

> 对应《爱管理_三大AI智能体功能设计.md》第 4 章(功能定位/数据输入/工作分析/难度分析/动态画像/团队风险/统一审核)。

## 这是什么

画像智能体回答三个问题:**每个人在一段时间内做了什么、承担了多大难度的工作、项目当前有什么风险**。
它不统计提交次数,而是基于活动事实、任务状态、难度评估与成员容量做证据化分析——每条结论都带依据,数据不足时如实说明,不编造。

## 核心能力(与设计文档的对应)

| 能力 | 文档章节 | 实现 |
|---|---|---|
| 成员工作摘要 | 4.3 | 按时间范围输出每人的活动明细(事实层)+ 归纳推断(带依据),未关联任务的活动单独提示 |
| 任务难度分析 | 4.5 | 按工时/依赖数/核心模块/阻塞/跨周自动评分定级(low/medium/high/extreme),依据逐条可追溯;人工修正永久优先 |
| 提交异常模式 | 4.6 | 识别「活动未关联任务」等模式,输出证据化描述而非评判个人 |
| 动态能力画像 | 4.7 | 擅长方向/难度承受/交付及时性/负载/推荐任务类型,每次分析落快照,可按时间回看变化 |
| 团队风险与协调建议 | 4.8 | 负载过高(≥90%)/关键单点依赖(≥2 项高难度)/任务长期无进展(进行中但 7 天无活动),每条带证据+推断+建议行动 |
| 时间范围查询 | 4.9 | 任意起止日期,前端默认当月 |
| 统一审核中心接入 | 第 5 章 | 团队风险可一键转成待审建议(kind=profile),由 admin/owner 采纳/拒绝;采纳后写入需求池,全程留痕 |

## 使用入口

前端 **AI 助手 → 画像智能体** 面板:选时间范围 → 查询(预览)/触发正式分析(留痕)→ 切成员看摘要与画像 → 展开难度分析 → 风险建议送审(去「AI 审核中心」处理)。

## API 一览

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/profile-agent/activities` | 录入活动事实(commit/pr/review/bugfix/task_done/note) | 登录成员 |
| GET | `/api/profile-agent/activities?userId=&start=&end=` | 活动列表 | 任何登录用户 |
| GET | `/api/profile-agent/difficulty` | 全量任务难度(AI 评估+人工覆盖优先) | 任何登录用户 |
| PATCH | `/api/profile-agent/difficulty/{taskId}` | 人工修正难度(admin/owner) | admin/owner |
| GET | `/api/profile-agent/analysis?start=&end=` | 整包分析预览(不留痕) | 任何登录用户 |
| POST | `/api/profile-agent/analysis/run?start=&end=` | 正式分析(留痕,失败可重试) | 任何登录用户 |
| GET | `/api/profile-agent/runs` | 分析运行记录(最近 20 条) | 任何登录用户 |
| POST | `/api/profile-agent/risks/submit-suggestions?start=&end=` | 团队风险 → 送审 | 登录成员 |
| GET | `/api/profile-agent/snapshots?userId=` | 画像快照历史 | 任何登录用户 |

## 数据表(均幂等建表,见 `db/schema.sql`)

- `activity_records` — 活动事实(手动/导入);task_id 可空,空即异常模式证据
- `difficulty_assessments` — 难度评估;`assessed_by=manual` 永远优先于 ai
- `profile_snapshots` — 画像快照(按时间范围)
- `profile_agent_runs` — 分析运行留痕(成功/失败均可重试)
- 另:`meeting_suggestion_records.meeting_id` 改为可空,使非会议来源的建议(画像智能体)能进入统一审核流

## 边界与原则

- 客观事实与 AI 推断分层输出,推断必须带依据;
- 提交次数 ≠ 工作量 ≠ 工作质量;
- AI 只建议,任务重新分配等正式变更由人工在审核中心确认后执行;
- 暂无数据时明确提示,不臆测。
