# AI 任务提交与成员能力画像智能体 · 介绍

> 对应《爱管理_三大AI智能体功能设计.md》第 4 章(功能定位/数据输入/工作分析/难度分析/动态画像/团队风险/统一审核)。
> 本文档随实现进度更新;当前已覆盖 4.1–4.12 全部可落地项(缺数据源的项如实说明,不臆造)。

## 这是什么

画像智能体回答三个问题:**每个人在一段时间内做了什么、承担了多大难度的工作、项目当前有什么风险**。
它不统计提交次数,而是基于活动事实、任务状态、难度评估与成员容量做证据化分析——每条结论都带依据,数据不足时如实说明,不编造。

## 核心能力(与设计文档的对应)

| 能力 | 文档章节 | 实现 |
|---|---|---|
| 成员工作摘要 | 4.3 | 按时间范围输出每人的活动明细(事实层)+ 归纳推断(带依据),未关联任务的活动单独提示 |
| 成员贡献分析 | 4.4 | Review 参与度、缺陷修复数、返工提示(同任务多次 bugfix)、按时交付(项目相对周换算)、预计工时口径说明、**协作贡献**(参与他人任务 Review 的次数与对象) |
| 任务难度分析 | 4.5 | 按工时/依赖数/核心模块/阻塞/跨周自动评分定级(low/medium/high/extreme),依据逐条可追溯;人工修正永久优先 |
| 提交异常模式 | 4.6 | 未关联任务、同标题重复提交、提交信息不清晰(标题过短/占位词)、任务完成但无代码活动、返工、延期;输出证据化描述而非评判个人 |
| 动态能力画像 | 4.7 | 擅长方向/难度承受/交付及时性/负载/推荐任务类型,每次分析落快照;**快照趋势**:相邻快照对比给出画像变化原因;**成员纠正机制**:成员可对 AI 画像(擅长方向等)提交纠正,永久保留并展示在画像旁(本人或 admin/owner) |
| 团队风险与协调建议 | 4.8 | 负载过高(≥90%)/关键单点依赖(≥2 项高难度)/任务长期无进展(7 天无活动)/**高难度任务缺 Review**/**临近或超过计划截止周未完成(里程碑风险)**,每条带证据+推断+建议行动 |
| 时间范围查询与对比 | 4.9 | 快捷周期(本周/本月/近 30 天)+任意起止日期;本期 vs 上期对比(活动量/Review/缺陷修复/完成任务/完成率/预计工时/未关联活动/高难度承担),实际完成工时缺数据源时如实说明 |
| 贡献活动可视化 | 4.10 | **贡献绿格子热力图**(按日聚合 commit/pr/review/bugfix/task_done/note,点击某天查看当天活动);明确标注「绿格子=活动分布,不等于工作质量」 |
| 数据输入 | 4.2 | 活动事实支持**批量导入**(单次 ≤200 条,source=import);实际工时/测试覆盖率/真实 GitHub 事件暂无数据源,文档已说明数据不足口径 |
| 统一审核中心接入 | 第 5 章 | 团队风险可一键转成待审建议(kind=profile),由 admin/owner 采纳/拒绝;采纳后写入需求池,全程留痕 |

## 使用入口

前端 **AI 助手 → 画像智能体** 面板:选时间范围 → 查询(预览)/触发正式分析(留痕)→ 切成员看摘要/画像/异常模式 → 绿格子热力图点击看当天 → 展开难度分析 → 展开「本期 vs 上期」对比 → 风险建议送审(去「AI 审核中心」处理)。

## 数据表(均幂等建表,见 `db/schema.sql`)

- `activity_records` — 活动事实(手动/导入);task_id 可空,空即异常模式证据
- `difficulty_assessments` — 难度评估;`assessed_by=manual` 永远优先于 ai
- `profile_snapshots` — 画像快照(按时间范围,趋势对比数据源)
- `profile_agent_runs` — 分析运行留痕(成功/失败均可重试)
- `profile_corrections` — 成员画像纠正(文档 4.7 纠正机制,永久保留)
- 另:`meeting_suggestion_records.meeting_id` 改为可空,使非会议来源的建议(画像智能体)能进入统一审核流

## 边界与原则

- 客观事实与 AI 推断分层输出,推断必须带依据;
- 提交次数 ≠ 工作量 ≠ 工作质量;绿格子 ≠ 能力评分;
- AI 只建议,任务重新分配等正式变更由人工在审核中心确认后执行;
- 暂无数据时明确提示,不臆测(如实际完成工时、测试覆盖率、真实 GitHub 事件);
- 难度/画像均可由人工修正,人工结论永久优先于 AI 推断。
