# 五类会议 Agent 试用指南

适用于当前 Vue 前端、Java 业务服务和 ai-service Python 分析服务。五类会议均遵循：保存会议文本 → 分析生成提案 → 人工审核 → 单独执行 → 核对业务结果和审计。分析成功或审核通过都不等于已经执行。

## 启动与配置

先按仓库《上手指南_克隆后如何运行》启动 MySQL、Java 和前端。已有日常服务无需重复启动；新装环境先安装 frontend 和 ai-service/requirements.txt 依赖。Java 必须使用包含五类会议表和接口的当前构建，不能仅更新前端后继续运行旧 jar。Java 默认8080、MySQL默认3307；数据库配置以实际 DB_URL/DB_USER/DB_PASSWORD 为准。

**还需单独启动 Python 服务。** Java 终端中的环境变量不会传给另一个终端；只修改 backend/.env 也不会自动更新运行中的进程。在仓库根目录打开新的 PowerShell，执行以下命令：只读取三项模型配置，不显示密钥，不启动历史 backend 服务。

```powershell
# 只检查启动条件，不启动服务、不调用模型
ai-service/.venv/Scripts/python.exe ai-service/start_service.py --check-only
# 检查通过后，在当前终端运行服务
ai-service/.venv/Scripts/python.exe ai-service/start_service.py
```

入口相对自身位置寻找 `backend/.env`，只加载AICAP_LLM_API_KEY、AICAP_LLM_BASE_URL、AICAP_LLM_MODEL；文件中出现的值覆盖当前进程同名环境变量，不解析变量表达式。默认文件不存在时使用进程环境；指定 `--env-file 路径` 的文件必须存在。用 `--environment-only` 可完全跳过文件。Java地址可通过 `--java-url http://127.0.0.1:8080` 或AICAP_JAVA_BASE_URL指定，Python监听端口可用 `--port 8090` 设置，始终只监听127.0.0.1。

检查包括依赖可导入、模型配置格式、Java `/api/health` 返回成功和监听端口可用。启动时保留已绑定端口交给Uvicorn，等待其“Application startup complete”确认；检查模式结束即释放端口，所以检查通过不预留之后启动的端口。缺依赖提示安装requirements.txt，缺配置或Java不可用时返回非零退出码；不会自动安装、杀进程或调用模型验证余额/密钥。Java健康接口也不证明数据库迁移或五类接口均就绪，完整链路仍以登录后分析保存为准。

三项配置分别为密钥、供应商兼容接口地址和模型名称；更换后重启 Python。保留该终端，Ctrl+C停止。8090被占用时先辨认是否已运行正确服务；不要同时启动历史FastAPI后端占用此端口。前端开发代理默认将 `/meeting-ai` 发到127.0.0.1:8090；若改Python端口，需在启动Vite的终端设置 `AICAP_AI_PROXY_TARGET` 并重启Vite。生产部署也需配置这一代理路径。

检查 `http://127.0.0.1:8080/api/health` 和 `http://127.0.0.1:8090/health`。后者只表示进程存活；登录后成功分析并保存记录，才能确认模型与Java鉴权链路可用。Python缺密钥会明确报错，不会自动产生演示提案。

## 页面通用步骤

1. 打开前端 `/#/ai`，登录并确认在线。离线演示不能用于验收真实写入。
2. 在会议智能体保存标题和文本，选择该已保存会议，检查显示的原文。录音上传不代表已转写，当前流程以已保存文本为输入。
3. 按下表选择会议入口。按需选择Sprint；未知时留空，不能把当前Sprint当作需求的默认排期。
4. 分析保存后，核对摘要、待确认问题、逐项原文证据及提案。没有明确决定时无提案是有效结果，不应通过改写原文强行生成。
5. 管理员或负责人逐项选择接受、修改后接受或拒绝。修改需实质变更并填写原因；原提案保留。审核决定提交后不可覆盖。
6. 对已批准提案单独点击“执行已批准变更”，等待结果确认。核对故事或行动项及日志编号；刷新页面后记录仍应存在。

## 五类会议范围与试用样例

下面故事编号需换成实际存在且状态匹配的故事。建议在试用库操作；真实模型措辞及提案数量可能与示例不同，仍须逐项核对。每个场景独立检查前置状态，不要求在同一故事上连续执行。

| 类型/页面入口 | 当前支持的结果 | 示例文本与核对点 |
| --- | --- | --- |
| Daily Scrum / 分析每日站会（默认展开） | 更新已有故事状态 | `US13今天开始开发。` 若原为待办，执行后进行中；阻塞不是第四种状态，未验收不能直接视为完成。 |
| 打开会议 Sprint Planning | 修改已有故事Sprint | `决定将US13调整到Sprint 3。` 可人工修改目标Sprint；执行仅改排期，不修改状态或自动分配任务。 |
| 打开会议 Sprint Review | 将明确验收通过的故事标为完成 | `US13已完成开发并验收通过。` “基本完成/等待验收”不应产生完成提案；执行后检查完成状态及日志。 |
| 打开会议 Sprint Retro | 创建独立改进行动项 | `决定完善发布检查表，负责人和截止时间待确认。` 允许未知负责人/截止时间；人工可补充，执行后查看行动项及创建审计，不创建故事。 |
| 打开会议 Backlog Refinement | 创建已确认的新故事 | `决定新增周报导出需求，其他字段待确认。` 审核时补齐描述、验收标准、优先级、Sprint和活动，执行后新故事为待办且未分配负责人。已有故事修改/拆分不伪装成新增。 |

Retro使用“查看行动项审计”核对创建载荷；其后续状态流转尚未实现。Refinement分别展示原提案和批准后的故事；同名已存在时不能重复创建，同义重复仍依赖模型判断和人工审核。新故事的验收要求表示未来验收条件，不代表已通过验收。

## 角色与入口区别

| 角色 | 保存/分析会议 | 审核/执行 | 查看记录 |
| --- | --- | --- | --- |
| admin、owner | 可以 | 可以 | 可以 |
| member | 可以 | 不可以 | 可以 |
| viewer | 不可以 | 不可以 | 可以 |

五类新流程仍在会议工作区各自面板内审核和执行。提案审核中心会聚合五类分析、Assignment 与通用建议的现有状态，并可从队列深链回到来源分析；实际审核和执行继续调用来源流程原接口。旧“分析会议”运行记录与手动建议仍保留在会议工作区。新流程无需GitHub令牌；Java旧启动脚本中的GitHub配置属于其他功能。

## 失败后如何继续

删除规则：管理员/负责人可删除没有五类分析或已保存分配建议的会议。只要已保存Daily、Planning、Review、Retro、Refinement分析或Assignment建议（包括无变更、已拒绝、未执行的记录），后端返回409并保留会议原文及审核执行审计。页面会说明原因，保留当前选择；需要整理新内容时新建会议。此保护沿用数据库关联约束，没有新增归档或强制删除功能。没有上述记录时仍按旧逻辑清理录音和旧建议，已产生的需求池条目保留。Assignment只读查询不产生记录，也不阻止删除。

| 页面现象 | 下一步 |
| --- | --- |
| 没有可分析会议 | 先保存文本并选择已保存会议；只在输入框填写但未保存不算完成。 |
| 401/登录过期 | 重新登录，再查看当前会议的处理记录。 |
| 403或没有审核按钮 | 核对登录角色；member不能审核或执行。 |
| 模型未配置/供应商超时 | 检查Python进程配置并重启；不要将密钥填入会议原文。 |
| “未能确认分析保存结果” | 使用“重试本次分析”，保留同一请求号；同一浏览器标签页刷新可恢复，清除会话存储可能丢失请求号。 |
| “未能确认审核/执行结果” | 先刷新处理状态核对；需要重试时使用同一提案和决定，不另建会议绕过不确定结果。 |
| 快照冲突/同名冲突 | 检查实际故事状态或同名故事，再重新分析和审核；不要覆盖历史决定。 |
| 执行已确认但看板刷新失败 | 使用“刷新看板和日志”，不需要再次创建业务对象。 |
| 已批准但没有业务变化 | 检查是否尚未单独执行；审核只保存决定。 |
| 删除返回409，要求保留原文与审计 | 该会议已保存五类分析，不能删除；查看历史记录或新建会议继续整理。 |

## Assignment技能候选试用

在AI页面选择已保存会议，点击“打开分配候选”。管理员、负责人和成员可选择一条故事，填写技能要求（维度、名称、最低等级），再点击“查询分配候选”。目标Sprint可保留未知；最低等级初始为3，可按实际要求修改。技能名与画像按去除首尾空格、忽略大小写的名称匹配，不推断别名。

页面按达到要求的项数排序，同分并列，显示每项画像等级和现有任务。六周容量只是原始事实，不能当作Sprint剩余容量；“容量未知”也不代表零负载。画像无满足记录不代表成员不具备能力。只读查询不会修改负责人。

需要分配时，点击“保存分配建议”。保存会重新计算，在下方“已保存的分配建议”核对实际保存的候选和负载快照。管理员/负责人选择成员、填写理由、勾选知悉容量未知后提交审核，也可填写理由拒绝。批准后再点击“执行已批准分配”，成功显示故事、负责人和日志号，并刷新看板；不会自动修改故事Sprint或关联任务负责人。

保存结果不确定时使用“重试保存分配建议”，刷新页面后仍沿用原请求条件和编号。审核/执行结果不确定时先点击“刷新分配记录”，核对是否已提交；可重试相同决定或同一建议。故事已变化或成员变成只读角色时执行返回冲突，应重新查询保存并审核。历史快照保留，不覆盖旧决定。详见[规则与接口](会议Agent_AssignmentEngine规则与接口.md)。

## 验收依据与限制

隔离真实服务测试运行方式和逐次证据见 [真实服务验收](../qa/DAILY_LIVE.md)。其浏览器、Python、Java、JWT、MyBatis和MySQL均为真实服务，模型为固定HTTP响应，只证明业务闭环。真实模型质量另见 ai-service/evals 下 Daily、Planning、Review、Retro、Refinement 的质量报告；仍保留部分语义待办，不能取消人工审核。

当前没有宣称完成多需求长会议全量验收、Retro后续状态流转或Refinement已有故事修改/拆分；LangGraph检查点恢复也未实现。分析请求幂等恢复与图检查点恢复是不同能力。

2026-10-01补充：Refinement已有一次真实模型到页面审核执行的隔离端到端验证，通过预设测试补齐内容自动操作人工审核界面，实际创建故事并核对日志。复现使用显式--real-model开关，最多一次供应商调用，详见上述真实服务验收文档。它不替代真实用户试用或复杂语义评测。
