## 口径裁决（重要）

**整理时发现同一件事被多份文档重复定义且互相冲突，以下为裁决结果：**

| 争议点 | 各方说法 | **裁决** |
|---|---|---|
| 有几个智能体 | 「三大」(9/6 设计稿) / 「只有两个」(需求基线 v2.0) / 「三个：会议·画像·提交」(README) / 「五个：含 Risk·Review」(9/19 扩展设计) / 「四类：主管+会议两代+画像+画图」(落地方案) | **3 个同事（会议 / 画像 / 画图）+ 1 个主管**。RiskAgent、ReviewAgent **从未实现且已不再计划** |
| 第二个智能体叫什么 | AI 项目规划画布智能体 / PlanningAgent / DrawingAgentView / 画图智能体 | **画图智能体**（代码标识 PlanningAgent，前端路由统一改 `planning-agent`） |
| 「任务提交」是不是独立智能体 | 是（README 口径）/ 否（9/6 设计稿把它并入画像） | **否**。它是画像智能体的一项能力，前端保留「任务提交分析」入口 |
| 进度看哪份 | 实施计划说「S3 之后以落地方案 §7 为准」；落地方案说「S4′ 起看我」 | **02-契约/主管智能体_落地方案_v1.0.md §7** 为唯一口径；实施计划保留作原设计追溯 |
| 老会议 Agent | 「两代并存」（落地方案 §两代并存段） | **已于 2026-10-13 删除**，仅 ai-service 一条链路 |

**已删除的过期文档**：根目录 `爱管理_依据实验指导书的详细规划_v1(1).md`（与归档目录内备份 md5 完全相同）。
