# 爱管理 · 故事地图「总览模式 + 马甲图层」设计规格

> 日期:2026-09-15 · 状态:已实施并回归(前端 E2E 41 条 + 后端契约 128 条 + 验收 8 条全绿)
> 依据:`docs/用户故事地图看板-项目管理知识摘要.md`(Patton 用户故事地图三层结构 / 切片语义 / 业界着色维度 / 紧急度阈值惯例 / 紧凑视图最小信息集 / 反模式)
> 实施提交:见本分支 `feat/story-map-overview-skins`

## 1. 问题

故事地图已经有 Patton 的两维结构(横轴 = A1–A5 骨干活动,纵轴 = Sprint 1/2/3/4+ 发布切片),但**只有"展开"一种粒度**:

- `.mapcard` 固定 148px,`.mapcell` 纵向堆叠;最挤的一格 `A4 × Sprint 2` 有 6 张卡 → 单格 935px;
- 整图实测 **2730px**,而视口只有 900px —— **要滚 3 屏半才能看完 4 个切片**。

这正是项目管理理论里点名的反模式:「总览塞满文字 → 看不清切片分布这个形状」。而**切片分布恰恰是故事地图唯一不可替代的信息**。所以问题不是"缺少功能",而是**缺少缩放这一层**(Jira / Azure DevOps 都有 compact/expanded,Miro 靠 zoom)。

附带问题:地图只能看到"故事属性"(优先级/负责人/状态),看不到**风险分布**;敏捷工具惯例是用**单一着色图层 + 常驻图例**回答一个管理问题。

## 2. 目标与非目标

**目标**

1. 一个「▤ 详细 / ▪ 总览」切换按钮;总览下**每个活动格一条一行、标题完整显示不截断**,且**一条故事都不丢**。
   (**口径修订**:最初把总览定义为"整图压进一屏",靠格内 2 列换行实现;实际使用后改为**可读性优先** —— 2 列时每格只剩约 86px、标题被截成 3~4 个字反而看不清,而"高度可以变长"是用户明确接受的。现为单列 + 标题换行不省略,整图约 550px。)
2. 一套**马甲(着色图层)**:紧急程度 / 负责人 / Sprint / 无着色 —— **单选**,禁止叠加。
3. 格内排序:原次序 / 紧急程度 / 负责人。
4. 颜色之外必须有**字符标记**(色盲友好),图例**写明规则**而不只是颜色名。

**非目标(明确不做)**

- 不动状态看板(已按状态分列,再上色是冗余);不动后端;不改数据模型;不做拖拽改切片。

## 3. 项目管理依据 → 设计决策

| 理论要点 | 落到的设计决策 |
|---|---|
| 横轴=叙事流程顺序,不可被拖拽改变 | 地图只保留"点卡编辑",不引入任何横向拖拽;排序是**格内**排序,不改变骨干顺序 |
| 纵轴切片语义 = "这条线以上先做" | 四个切片是既有结构,本次不动;马甲只改**呈现**不改结构 |
| 着色做成单图层 + 常驻图例,禁止叠加 | `#skin` 单选;每卡恒有**恰好 1 个** `tone-*` 类;`#maplegend` 常驻并带实时计数 |
| 图例必须写明阈值规则 | 紧急度图例直接写「截止周 < W3」「截止周 ≥ W6」等规则文本 |
| 色盲友好:红绿是最差组合,不得只靠色相 | 每张卡除颜色外必须带字符标记(`! ▲ · ○ ? ✓`)或成员/切片标记(`P1` / `S1`) |
| 灰色 = 未知,不等于安全,须单列 | 「后续路线(无排期)」单独成档,**不并入「宽松」** |
| 紧凑视图保留 3~5 个字段,隐藏描述/验收 | 总览只渲染「标记 + 编号 + 标题(截断)」;`compact` 态**不渲染** `.carddesc` / `.mapstatus` |
| 未排期项不得硬塞日期 | Sprint 4+ 的故事 → 无排期(灰),不编造截止周 |
| 反模式「缺少当前迭代线」 | 工具栏常驻 `#todayanchor`(今天 · 第 N 周 · Sprint M) |

## 4. 方案选型(为什么这样切)

**粒度实现:两套模板 vs CSS 缩放 vs 换组件**

- 选**同一组件两态**(`StoryCard` 增 `compact`/`skin` 两个 prop),而不是新建一个 `MiniCard` 组件或整体 `transform: scale()`。
  理由:① 一张卡的"编号/标题/马甲"逻辑只有一处,E2E 里 `.card` 计数在两种粒度下都必须等于故事总数,共用选择器才守得住这条不变量;② `scale()` 会同时缩放文字与边框,像素风下会糊,且命中测试与截断都不可控;③ 组件数不增加,回归面最小。

**着色计算放哪:组件内 vs 独立纯函数模块**

- 选**独立纯函数模块** `data/boardSkins.js`(成员色/姓名由调用方注入),`data/planCalendar.js` 承载日历口径。
  理由:着色规则是**可推演、可测试**的口径而不是模板细节;测试侧可以按同一口径**独立复算**再与界面比对(本套件一贯做法:`featureSubs` / `taskStatusKey` / `expectedWeightedPct`),避免把 `10/11/11/3/2` 这类数字写死在断言里。

## 5. 设计

### 5.1 数据层 `frontend/src/data/planCalendar.js`(新增)

项目此前**没有任何"现在"的锚点**:`StoryOut` 无日期字段、`Task` 只有 `week_start/week_end`、全仓唯一叫 deadline 的 `deadline_text` 是会议智能体的自由文本(未解析)。故显式定义唯一锚点:

- 项目起点 `PROJECT_START = 2026-08-31`(周一);每 2 周一个 Sprint(W1–W2=S1 / W3–W4=S2 / W5–W6=S3,与 `derivedTaskSprints` 同式)。
- `currentWeek(now)`:起点所在周为 W1,早于起点夹到 W1,**上限不夹紧**(真实日期超出六周时"逾期"应如实反映)。
- `deadlineWeekOf(story, tasks)`:优先取所挂 feature 子任务的最晚 `week_end`(12 条有真实排期);无子任务退回切片末周(其余 25 条);Sprint 4+ → `null`(无排期)。
- `urgencyOf(...)`:gap = 截止周 − 当前周 → `<0` 逾期 / `=0` 本周到期 / `1–2` 临近 / `≥3` 宽松;已完成单列;无排期单列。
- `window.__AICAP_TODAY__` 可覆盖「今天」(与既有 `__AICAP_API_BASE__` 同一注入约定)→ E2E 固定为 `2026-09-15`(W3),否则断言会随真实日期漂移。

### 5.2 呈现层 `frontend/src/data/boardSkins.js`(新增)

- `SKINS` = 紧急程度 / 负责人 / Sprint / 无着色(默认**紧急程度**);`SORTS` = 原次序 / 紧急程度 / 负责人。
- `skinOf(story, ctx)` → `{tone, glyph, label, detail}`;`legendOf(skin, data, ctx)` → 图例行(带实时计数);`sortStories(list, sortBy, ctx)` → 不改动原数组。
- 负责人图例带**兜底行**:若某故事负责人不在成员表内,补「未知成员」行,保证「图例计数之和 == 当前筛选范围」这条可相加校验永远成立。
- `tone` 只是一组 CSS 类名(`tone-red/orange/yellow/green/blue/pink/gray/muted/s1..s4`),色值全部复用既有设计变量,不新增色板。

### 5.3 组件与样式

| 文件 | 改动 |
|---|---|
| `components/board/StoryCard.vue` | 增 `compact` / `skin`;总览渲染单行 `.chip`(标记 + 编号 + 标题截断);详细态只在 `.cardtop` 增一个 `.sking` 字形 + 左侧色条。**不往 `.mapstatus` / `.owner` 里加任何字符**,避免破坏既有断言 |
| `components/board/StoryMapGrid.vue` | 增 `density` / `skin` / `sortBy` / `nowWeek`;渲染常驻图例 `#maplegend`(含 `#legendsum` 守恒校验);`#map` 加 `compact` / `skinned` 类 |
| `components/board/BoardToolbar.vue` | 增 `#density-detail` / `#density-compact` 分段按钮、`#skin`、`#sortby`(仅地图视图显示)、`#todayanchor` |
| `views/BoardView.vue` | 持有三个状态;切总览时 `#mappanel.scrollIntoView()`(让开吸顶顶栏:`scroll-margin-top:72px`) |
| `styles/index.css` | 马甲色板(`--tone` + 单条 `var(--tone)` 规则)、图例、`.chip`、`.mapgrid.compact` |

### 5.4 关键实现细节(踩过的坑,写进注释以免复发)

1. **总览下"压高度"与"看得清"是会互相挤压的两个目标,最后选了看得清**。第一版为把整图压进一屏,用 `auto-fill` + `minmax(80px)` 在格内排 2 列,并为此写了一大段阈值推导(活动列宽约 175~202px,`auto-fill` 还把 gap 算进单列宽度,`min=94` 时是 1.83 列会退化成单列…)。结果实测:2 列时每格只剩约 86px,标题被截成 3~4 个字 —— **整图 337px 一屏放得下,但看不出是哪条故事**,总览的意义就没了。现改回**单列**(1 列 `1fr`,每格一条一行),标题 `overflow-wrap:anywhere` 换行、**不省略**,整图 2730px → 约 550px(仍压缩到 1/5),代价是恢复纵向滚动。教训:压缩比的分子分母要选对 —— 该压的是"每条信息占多高",不是"每行能塞几条"。
2. **切片标签列的 `.small` 是 13px 字号**而列宽只有 64px → 折成 3 行,把整行从 ~58px 顶到 89px,是总览高度最大的单点瓶颈。总览下压成单行 + 省略号。
3. **`addInitScript` 每次导航都会重跑**,所以"改 `window.__AICAP_TODAY__` 再 reload"验证跨日期是无效的;必须用**独立 context**(`FE-BRD-11` 就是这么写的)。

## 6. 验证

- 后端契约 `mvn -o -B test`:128 条;前端基线 E2E `qa/`:41 条(FE-BRD 由 7 → 11);验收 `frontend/e2e-verify`:8 条。合计 **177**。
- 实测效果(1280×720,与 E2E 默认视口一致):详细态整图 **2730px** / 最挤单格 935px → 总览态整图 **547px**(压缩到 1/5),16 个有卡片的活动格**全部单列**,37 条故事**标题零截断**(超长标题折成 2 行:chip 高 22px 或 37px),横向零溢出;卡片数两种粒度下恒为 37。总览整图高于 720px 视口,纵向滚动 —— 这是**读得清**换来的,已确认接受。
- **每条新断言都做了变异验证**(改动锚点逐条还原后必须变红,共 8 条全部复现):

| 变异 | 期望红灯 | 实际报错 |
|---|---|---|
| 标题退回 `nowrap` + 省略号 | FE-BRD-08 | 「总览下标题不得被截断(长标题应换行而不是省略)」 |
| 格子退回 `minmax(80px)` 两列 | FE-BRD-08 | 「每个活动格只能排一列」 |
| 总览态不再降级渲染 | FE-BRD-08 | 「每张卡都要有标题元素」 |
| 马甲字符标记写错 | FE-BRD-09 | 「US01 的 data-skin-key」 |
| 图例漏掉「无排期」档 | FE-BRD-09 | 图例行数断言不符(计数不守恒) |
| 短路排序函数 | FE-BRD-10 | 「按负责人排序:格内按 owner_id 升序,未分配排最后」 |
| 写死「今天」锚点 | FE-BRD-11 | 锚点文本断言不符(W1/W5 不再有差异) |

> 说明:`FE-BRD-08` 最初还断言过「总览整图落在视口内」,口径修订后该断言**已删除**(它锁的是被推翻的设计);取而代之的是「每格单列 + 标题零截断 + 整图 < 详细态的 1/4」。

## 7. 已知局限(未做,不是遗漏)

1. **紧急度与切片行高度共线**:34/37 条故事的截止周只能由切片末周推出(数据里没有故事级截止日期),所以分档呈现为"按切片行分带",只有 `US14`(S3 但挂 T12 截止 W5)落在本行之外。带边界会随周推进(W1 逾期 0 → W5 逾期 20 → W7 逾期 32),回答的是"此时此刻先做哪一行";要真正与 Sprint 图层拉开差距,需要给故事加**可写截止日期**(schema 改动)。已登记为 `FE-FE-03` / `Q-17`。
2. **总览下仍不显示描述 / 验收 / 状态行**:那些信息切「详细」或点开卡片即可(这是刻意设计,不是压缩损失)。标题已改为完整显示(超长折行),长标题可能占两行、使该格变高,属预期。
3. **窄窗口(<1100px)下总览会退化成单列**、整图变高:这是有侧栏的 8 视图布局的固有限制,不是本次引入的;横向本来就靠 `.mapwrap` 滚动。
4. 未做「当前迭代线」在地图上的**图形化**标记(只在工具栏给了 `#todayanchor` 文字),也没有把不可行的 Won't 项单独收纳区(需求池已承担该职责)。
