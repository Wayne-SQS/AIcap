## 1. 先钉死产品定位

> **一个由「本」统筹的 AI 团队办公室 —— 三个智能体同事各司其职，你只跟「本」说话。**

三条不可动摇的产品定义：

1. **单入口**——人只跟主管对话，不直接面对三个执行者。
2. **全知**——主管能读到所有同事的产出与项目事实。
3. **零直写**——任何会改动项目正式数据的结论，先过审批队列，由人拍板。

当前所有"乱"，本质都是这三条没被贯彻：
入口有 6 个（违反 1），三个同事各自对外（违反 2），老链路直连 mapper（违反 3）。

## 3. 优秀智能体应用的衡量框架

| 维度 | 优秀标准 | AIcap 现状 |
|---|---|---|
| **入口收敛度** | 用户知道"找谁" | 🔴 6 个 AI 入口，2 个隐藏 |
| **首次价值时间(TTV)** | < 5 分钟感受到价值 | 🔴 需配密钥 + 起 4 容器 |
| **过程可观测** | 知道它在干什么 | 🔴 事件流零消费 |
| **结果可信** | 敢直接用 | 🟡 运行时校验已删 |
| **容错明确** | 失败时知道怎么办 | 🟡 503 如实但不友好 |
| **人格一致** | 像同一个产品 | 🔴 命名四套 |
| **能力可发现** | 知道它能干啥 | 🟡 靠菜单猜 |
| **协作可编排** | 能一句话调多人 | 🟡 只有 2 枚触发工具 |

## 4. 差距清单：还差什么

### P0 · 决定"是不是一个产品"

**① 入口收敛（最关键）**
- 现状：「智能协作」6 项（AI 工作台 / 会议工作区 / 任务提交分析 / 成员画像分析 / 画图智能体 / 提案审核中心）+ 隐藏的 `ai-demo` / `project-generator`
- 应改为：**1 个悬浮入口「本」** + 对话框；其余入口降级为对话框里的能力，或保留为"深度工作台"（供想细看的人用）
- 理由：这是"办公室"隐喻能否成立的唯一支点

**② 对话过程时间轴**
- 现状：后端 SSE 就绪（11 类事件 + seq），前端**零** EventSource
- 应补：对话框内按 seq 渲染"本 → 找谁 → 说了什么 → 拿回什么"
- 理由：这是"办公室"的**可观测性**——看不见交流过程，就还是黑盒

**③ 运行时证据校验（防幻觉护栏）**
- 现状：随老包删除，新链路只有离线评测
- 应补：三条检查（evidence 字段集恰好等于 `{segment_id, quote}`、quote 逐字命中、片段全覆盖）移植进 ai-service validate 节点
- 理由：主管要向人汇报，不校验等于"它编你也信"

### P1 · 决定"好不好用"

**④ 派活覆盖全部三个同事**
- 现状：`start_meeting_analysis` / `start_plan_draft` 两枚；`start_profile_analysis` 因画像域无后台消费者暂缓
- 应补：`ProfileWorkerTask` + 第三枚触发工具

**⑤ 主管记忆**
- 现状：画像有记忆层，主管没有
- 应补：会话级记忆——之前问过什么、派过什么活、结论是什么

**⑥ 编排层进生产**
- 现状：不在 `deploy/compose.yaml`，nginx 无 8100 路由
- 应补：compose 加服务 + nginx `location /orchestrator/`（`proxy_buffering off`）

### P2 · 决定"能不能讲"

**⑦ 老链路八项开放产出的取舍**（要不要补进 ai-service）
**⑧ 文档三层的收尾**（`docs/02-契约/会议Agent_外部功能基线与新架构落点.md` 需按"老包已删"重写）
**⑨ 统一对外文案**（README / 演示脚本 / 人格卡）

## 5. 优先级建议（附理由）

我建议 **只做 P0，做完后重新评估**，理由是：

| 排序 | 理由 |
|---|---|
| **① 入口收敛** | 阻断项。没有它，"办公室"故事只剩 PPT。且它是**纯前端工作**，不碰已稳定的后端 |
| **② 时间轴** | 和 ① 在同一处做，边际成本几乎为零（事件流后端已就绪） |
| **③ 证据校验** | 唯一需要动后端的一项，但改动面小且已有原始实现可移植 |
| P1/P2 | 做完 P0 后看剩余时间。**不要并行启动** —— 这正是"开发到一半反复改"的成因 |

**关键约束**：P0 三项**不动任何现有智能体的业务逻辑**。译 / 衡 / 绘 的实现保持冻结，只在其上加一层统一入口。这样即使 P0 中途停下，也不会破坏已能跑的部分。
