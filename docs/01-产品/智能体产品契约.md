## 1. 产品隐喻：一个办公室

整个系统的智能体部分按**一间办公室**来组织：

- **人（你 / 团队）只跟一个人说话** —— 主管智能体。
- **主管能看到其余同事的全部工作内容**，也能**主动去找他们要东西、派活**。
- **同事之间不直接对人说话**，他们的产出统一汇到主管那儿，由主管转述给人。
- 所有会改动项目正式数据的结论，**一律进审批队列，由人拍板**。

> 一句话：**人 ↔ 主管（唯一对话对象）；主管 ↔ 同事（全知 + 派活 + 启动服务）。**

## 2. 角色清单（只有 3 个同事 + 1 个主管）

| 角色 | 产品名 | 权威中文名 | 代码标识 | 一句话职责 |
|---|---|---|---|---|
| **主管** | **本** | 主管智能体 | Supervisor（原 OrchestratorAgent） | 对人沟通；看全部同事产出；派活；启动同事的服务 |
| 同事 1 | **译** | 会议智能体 | MeetingAgent | 把会议录音/转写变成结构化结论 |
| 同事 2 | **衡** | 画像智能体 | ProfileAgent | 说清每个人这段时间做了什么、难度如何、有什么风险 |
| 同事 3 | **绘** | 画图智能体 | PlanningAgent | 把项目数据/自然语言变成可交互的项目图 |

### 2.1 命名体系（必须遵守）

**产品名 = 单字，职能双关：**

| 产品名 | 字义 | 为什么是它 |
|---|---|---|
| **本** | 根本 / 本部 / 本位 | 全局的归口。它自己不干活，它知道谁该干什么 |
| **译** | 转译 / 口译 | 会议智能体不是"记录员"，是把口语译成任务、负责人、排期 |
| **衡** | 衡量 / 权衡 / 度量 | 它不"评价"人，它量化——难度几级、负载几成、延期率多少。**是尺子，不是法官** |
| **绘** | 绘制 / 图形 | 最直白的一个，比"画图智能体"少两个字 |

> 记忆点：**本**统管全局，**译**开会、**衡**看人、**绘**画图。

**废弃的旧名与别名**（出现在本文件之外即视为过时）：

- ❌ 「AI 项目规划画布智能体」→ ✅ **绘（画图智能体）**
- ❌ 「AI 任务提交与成员能力画像智能体」→ ✅ **衡（画像智能体）**，其「任务提交分析」是一项能力，不是独立同事

**唯一对外口径**：3 个同事 + 1 个主管。任何文档、UI、接口若出现第 5 个「智能体」概念，视为分叉，须先回来改本文件。

## 3. 三个同事的五要素

> 「目标用户 / 触发场景 / 输入 / 输出 / 用户拿到后做什么」——这是判断一个功能是否属于某个智能体的唯一标准。

### 3.1 会议智能体（MeetingAgent）

| 项 | 内容 |
|---|---|
| 目标用户 | 项目负责人、Scrum Master（会后整理时） |
| 触发场景 | 上传会议录音/转写，或主管转达「开个会整理一下」 |
| 输入 | 会议录音 / 转写文本、参会人、项目现有故事/任务/需求池/成员负载 |
| 输出 | 五类会议的类型化产出（每日站会状态更新 / 规划 Sprint 调整 / 评审验收 / 回顾行动项 / 细化新故事），每条带 `seg-N` 证据引用 |
| 用户下一步 | 在审核中心逐条采纳 / 修改后采纳 / 拒绝；采纳后同步到看板、甘特、需求池 |

**现行实现**：`ai-service/`（Python 8090，LangGraph），五类会议各一张同构 `StateGraph`。
**上一代**：Java `com.aicap.agent/` 已于 **2026-10-13 整包删除**。

### 3.2 画像智能体（ProfileAgent）

| 项 | 内容 |
|---|---|
| 目标用户 | 项目负责人（想知道谁干了什么）、成员本人（想核对/纠正） |
| 触发场景 | 周期自动分析、主管转达「查一下 X 最近的情况」、成员点「✓ 已完成」 |
| 输入 | `activity_records`（含 GitHub 同步）、任务与状态、难度评估、成员容量、画像快照、纠正历史 |
| 输出 | 工作摘要、贡献分析、任务难度分析、动态能力画像、团队风险与协调建议（**必须区分客观事实与 AI 推断**） |
| 用户下一步 | 核对事实、纠正误判、把协调建议送审核 |

**现行实现**：Java `profile/`（8 个只读工具，双模式：`GET /analysis` 零 LLM 预览 / `POST /analysis/run` 正式分析）。
⚠️ **缺口**：无后台消费者 → 主管暂时派不了活给它（见 §5）。

### 3.3 画图智能体（PlanningAgent）

| 项 | 目标 |
|---|---|
| 目标用户 | 项目负责人（排期与可视化时） |
| 触发场景 | 输入自然语言（「把权限模块推迟 3 天」），或主管转达「画一下当前计划」 |
| 输入 | 用户故事、任务、成员容量、依赖、Sprint、里程碑、优先级、难度 |
| 输出 | 故事地图、甘特图、成员任务图、UML 图，及**修改后的影响面分析** |
| 用户下一步 | 在预览上确认后导入（merge / replace） |

**现行实现**：Java `planning/`（规划 Agent + `/impact` 影响面分析 + confirm 后导入）+ `generation/`（项目生成）。
⚠️ 注：原始三大设计里的这个角色**长期零实现**（项目记忆 2026-09-25 记录），现有能力是由 `planning/` + `generation/` 两个包拼出来的。

## 4. 主管智能体（核心，不是第 4 个同事）

主管**不是**和三个同事并列的第四个执行者。它是**人与办公室之间的那扇门**。

### 4.1 三件事

| 能力 | 含义 | 现行落点 |
|---|---|---|
| **全知** | 能读到其余三个同事的全部工作内容 | `GET /api/agents/catalog` + 14 个只读工具 + `semantic_search` ✅ |
| **派活** | 让某个同事去干一件事 | 触发型工具 ⚠️ 只有 2 枚 |
| **启动服务** | 唤起某个同事的后台执行 | 同上 ⚠️ |

### 4.2 交互形态（用户确认的设计）

- 界面右下角（或左下）常驻一个**悬浮的小像素头像**，与整体像素风一致。
- 点开头像 → 展开**对话框**。
- 对话框里两件事：
  1. **问** —— 用自然语言问项目里的任何情况（进度、负载、风险、某次会议说了什么）。
  2. **派** —— 直接说「让会议智能体去分析一下这场会议」「让画像智能体查一下 XX 最近的情况」。
- **交流过程可见**：主管找了哪个同事、说了什么、同事回了什么、拿到什么结果 —— 以**时间轴**形式在同一个对话框里展示（对应后端 SSE 11 类事件信封 + `Last-Event-ID` 断线续传，关掉页面回来还能看见）。

### 4.3 权限纪律

主管**没有自己的身份**，它借提问者的工牌：

- 不建服务账号，Python 侧不持有长期凭证，把提问者的 JWT 原样转发给 Java。
- 工具接口不提供 `asUserId` / `onBehalfOf` 参数。
- 读 + 导出按提问者权限过滤，无需批准；**写库 + 开启采集（录音）必须经人批准**。
- 主管可以**创建会话**，但**不能开启采集**。

## 5. 已知缺口（本契约承认，不掩盖）

| # | 缺口 | 影响 | 建议 |
|---|---|---|---|
| 1 | **运行时证据校验已随老包删除** | 模型伪造 quote 可能查无此句而系统不报错，且**测试不会变红**（静默降级） | 把 `invented_assignment` / `invalid_evidence` / `incomplete_analysis` 三条检查移植进 ai-service 的 validate 节点 |
| 2 | **画像域无后台消费者** | 主管派不了活给画像智能体 | 加 `ProfileWorkerTask implements WorkerTask`（照 `PlanningWorkerTask` 抄）+ 第三枚触发工具 `start_profile_analysis` |
| 3 | **编排层未接线** | `/chat` 依赖密钥，未进 compose，前端零 SSE 消费 | 配密钥 → 加进 compose → nginx 加路由（`proxy_buffering off`）→ 前端悬浮头像 + 对话框 |
| 4 | **老链路开放类八项产出消失** | 若验收需要「任意会议 → 摘要+行动项」，新家无对应 | 评估是否要补进 ai-service，或明确放弃 |
